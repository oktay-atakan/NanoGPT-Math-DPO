# NanoGPT Math with Direct Preference Optimization

Fine-tuning a character-level NanoGPT model to solve simple arithmetic and algebra problems using preference-based training with Direct Preference Optimization (DPO).

This project extends the provided **NanoGPT-Math** starter repository by constructing a large preference dataset, implementing the DPO training pipeline, and evaluating the fine-tuned model on unseen arithmetic and algebra prompts.

## Overview

The original NanoGPT model is pretrained on question-answering data but is not trained specifically for mathematical reasoning. The goal of this project is to improve its ability to answer simple arithmetic and algebra questions using positive-negative response pairs.

Each training item contains:

- a **preferred response**, containing the correct solution and explanation;
- a **rejected response**, generated by the pretrained NanoGPT model.

The model is then fine-tuned so that preferred responses receive higher probability than rejected responses.

## Preference Dataset

The final dataset contains **100,004 positive-negative response pairs**.

The generated prompts cover nine question types:

1. Addition
2. Subtraction
3. Multiplication
4. Division
5. `x + a = b`
6. `x - a = b`
7. `a - x = b`
8. `x * a = b`
9. `x / a = b`

Approximately 100,000 prompts were generated programmatically. Rejected responses were obtained from the pretrained NanoGPT model, while preferred responses contain the correct mathematical solution and a short explanation.

The final dataset is stored in:

```text
dpo/pos_neg_pairs.json
```

## DPO Fine-Tuning

The model is fine-tuned using a preference-based objective that increases the relative log-probability of preferred responses compared with rejected responses.

Main training configuration:

```text
Epochs:        5
Batch size:    64
Learning rate: 1e-4
Optimizer:     AdamW
Beta:          0.5
Sequence length: 64
```

The training pipeline is implemented in:

```text
dpo/dpo.ipynb
```

After training, the fine-tuned checkpoint is saved as:

```text
dpo/dpo.pt
```

## Evaluation

The fine-tuned model was evaluated using a balanced held-out test set containing **45 prompts**, with five prompts from each of the nine question categories.

None of the exact evaluation prompts appeared in the preference training dataset.

In one stochastic evaluation run using the provided generation settings, the model correctly answered:

```text
26 / 45 questions
Accuracy: 57.8%
```

Performance was stronger on some algebraic multiplication and reverse-subtraction problems, while division-based problems remained more challenging.

Because generation uses temperature sampling and top-k filtering, the exact evaluation result can vary between runs.

## Limitations

The model is intentionally very small and does not perform exact arithmetic reliably in every case. In several incorrect responses, the model selects the correct mathematical operation but produces an incorrect numerical result.

Possible improvements include:

- adding more preference pairs for weaker question categories;
- targeted fine-tuning on multiplication and division;
- using a larger model;
- evaluating with deterministic decoding or multiple evaluation runs;
- expanding the dataset to more complex mathematical expressions.

## Running the Project

Place the pretrained NanoGPT checkpoint at:

```text
sft/gpt.pt
```

Then open:

```text
dpo/dpo.ipynb
```

and execute the notebook cells sequentially.

The notebook loads the pretrained model, loads the preference dataset, performs DPO fine-tuning, saves the resulting checkpoint, and evaluates the trained model.

A CUDA-capable GPU is recommended for training.
